If the banner is still on screen

A table that exists but still answers PGRST205 is a stale PostgREST schema cache: run notify pgrst, 'reload schema'; in the Supabase SQL Editor and reload.

The other cause is a dashboard that is not this build. Reload with Ctrl/Cmd-Shift-R (or open it in a private window): the banner's sentence changes as soon as the new dashboard.js is in the browser, and it names the table and the file rather than asking for schema.sql again. The full list, as SQL you can paste in the Supabase SQL Editor 
select expected.name as missing_table
from (values
  ('authors'), ('categories'), ('blogs'), ('comments'), ('galleries'), ('pdf_books'),
  ('submitted_blogs'), ('videos'), ('settings'), ('profiles'), ('user_notifications'),
  ('admin_messages'), ('music_tracks'), ('app_language_files'),
  ('forum_discussions'), ('forum_replies'), ('forum_categories'), ('forum_reactions')
) as expected(name)
where not exists (
  select 1 from information_schema.tables t
  where t.table_schema = 'public' and t.table_name = expected.name
)
order by expected.name;

An empty result means every table the dashboard reads exists.
