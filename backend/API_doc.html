Ningshing – API & Application Documentation

This document describes the backend APIs, the dashboard admin interface, and the mobile/web application usage.

Backend API

The backend is built with Node.js (Express) and Supabase (PostgreSQL). All endpoints are prefixed with /api.

Base URL

https://your-domain.com/api

Authentication

Most routes require a Bearer token obtained via POST /auth/login.

Endpoints Overview

  • Articles
    • GET /articles – List all articles (supports pagination, filtering by category, tag).
    • GET /articles/:id – Retrieve a single article with its HTML content.
    • POST /articles – Create a new article (requires auth).
    • PUT /articles/:id – Update an article.
    • DELETE /articles/:id – Delete an article.
  • Authors
    • GET /authors – List authors.
    • GET /authors/:id – Get author details.
    • POST /authors – Create author.
    • PUT /authors/:id – Update author.
    • DELETE /authors/:id – Delete author.
  • Categories
    • GET /categories – List categories.
    • GET /categories/:id – Get category details.
    • POST /categories – Create category.
    • PUT /categories/:id – Update category.
    • DELETE /categories/:id – Delete category.
  • PDF Books
    • GET /pdf-books – List available PDF books.
    • GET /pdf-books/:id – Stream a PDF file.
    • POST /pdf-books – Upload a new PDF book (requires auth).
  • Comments
    • GET /comments – List comments for an article.
    • POST /comments – Submit a new comment.
    • DELETE /comments/:id – Remove a comment (mod only).
  • Settings / System
    • GET /settings – App configuration (feature flags, URLs).
    • PUT /settings – Update settings (admin only).

Sample Request (cURL)

curl -H "Authorization: Bearer " https://your-domain.com/api/articles

Response Format

JSON objects use camelCase keys. Example article summary:

{
    "id": "c1d2e3f4",
    "title": "Understanding Bengali Typography",
    "authorName": "Saiful Islam",
    "category": "Culture",
    "readingTimeMinutes": 5,
    "imageUrl": "https://example.com/img.jpg"
  }

Dashboard (Admin) Documentation

The dashboard is a React admin panel that sits on top of the same backend. It provides CRUD interfaces for content managers and site admins.

Access

  • URL: https://your-domain.com/dashboard
  • Login credentials are provisioned by the super‑admin.

Features

  • Article Management – Create, edit, delete, and schedule articles.
  • Author Management – Add/remove authors, assign verification badges.
  • Category Management – Organize articles into hierarchical categories.
  • PDF Library – Upload, preview, and organize PDF books.
  • User Analytics – Basic stats (views, likes, comments) via GET /dashboard/analytics.
  • Comments Moderation – Approve/reject user comments.

API Proxy

The dashboard talks to the backend through a proxy under /api (same as the mobile app). No extra auth token is needed when the admin is logged in; session cookies handle permission checks.

Endpoints Used Internally

  • GET /api/articles – Populate the article list screen.
  • POST /api/articles – Save a draft or published article.
  • GET /api/authors – Dropdown for author selection.
  • GET /api/categories – Category tree for the sidebar.
  • GET /api/pdf-books – List books in the library.
  • POST /api/comments – Submit a comment for moderation.

UI Notes

  • All forms use react-hook-form with validation via yup.
  • Data tables are powered by react-table with server‑side pagination.
  • Dark mode is supported via the app’s theme toggle.

Mobile / Web Application Documentation

The Ningshing reader app (Android/ iOS / Web) consumes the backend APIs and provides a rich reading experience.

Entry Points

  • Home screen: / – displays hero carousel, featured articles, categories.
  • Article detail: /article/:id – full‑screen reading view.
  • Category browse: /category/:slug – list articles in a category.
  • Search: /search – full‑text search across titles and content.

Key Screens & Their Data Flows

  • Home Screen
    • Fetches GET /api/articles?isFeature=true for the featured rail.
    • Loads categories via GET /api/categories for the category rail.
    • AI Assistant button opens the bottom‑sheet described in the “AI Assistant” section.
  • Article Reader
    • Retrieves article via GET /api/articles/:id.
    • Renders HTML using the RichHtmlArticleBody component.
    • Voice synthesis uses the ArticleTtsController which calls the TTS engine.
    • Pull‑to‑refresh triggers GET /api/articles/:id again.
  • Category Screen
    • Lists articles filtered by the selected category.
    • Uses GET /api/articles?categorySlug=....
  • PDF Book Reader
    • Opens the PDF viewer described in the “PDF Viewer” section.
    • Downloads the PDF from GET /api/pdf-books/:id (streamed).
  • AI Assistant Bottom Sheet
    • Sends the user’s question to NinghsingCheAiAssistant.answerArticleSpecificQuestion which internally calls the backend AI service.
    • Answer is shown only if it originates from the current article; otherwise a “not from article” message appears.

Offline / Cache Strategy

  • Article lists are cached with Realm/MobX for quick re‑entry.
  • PDF files are stored in the app’s internal cache after the first download.
  • Auth tokens are stored securely via react-native-keychain (Android) / Keychain (iOS).

Error Handling

All API errors return a JSON object {error: "message", code: number}. The frontend displays a toast or snackbar with the user‑friendly message.

Versioning

API version is not yet versioned; breaking changes will be communicated via the changelog and a /v1 prefix may be added in the future.
